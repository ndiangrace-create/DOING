# DOING 2.0 世界樹 v11｜前台申請與智慧小幫手分離

日期：2026-08-22
狀態：Implementation / Release Ready 前

## 定案

1. 智慧小幫手保留，角色固定為「客服／導引」。
2. 智慧小幫手不得再作為申請必填、確認或阻擋條件。
3. 「我要申請」為獨立正式流程，不依賴客服對話完成度。
4. 前台不得顯示內部系統、模組、AI 規則、Core、SSOT、角色判斷或工程說明。
5. 一般使用者只需要看到自己要選什麼、填什麼、下一步會發生什麼。

## 正式前台申請流程

我要申請 → 選擇使用產品 → 選擇實際使用類型 → 填寫申請資料 → LINE 驗證 → Supabase 自動開通／例外人工複核 → 建立 organizer_owner → 我的 DOING → 對應產品。

## 移除的前台步驟

- 固定模組確認。
- 查看固定模組。
- 「這是不是我要申請的系統」二次確認。
- 智慧小幫手整理完成確認。
- AI／固定能力／模組架構說明。
- Market 的主辦／攤商角色詢問。

## 相容規則

- 後端若仍需要舊版 assistantAnalysis / helperUnderstanding 相容欄位，由前端依已選產品自動提供，不要求使用者額外操作。
- helperUnderstanding 明確記錄 customerServiceOnly=true、applicationGate=false。
- 不新增資料表，不修改既有正式業務資料。
- Supabase 仍是唯一正式業務資料來源。

## 智慧小幫手客服職責

可回答：
- 哪個產品適合我。
- 功能如何使用。
- 申請卡住怎麼處理。
- 報名／付款／現場／設定要去哪裡。
- 常見問題與真人客服分流。

不得：
- 阻止正式申請送出。
- 自行建立產品、模組或資料表。
- 將客服對話完成度當成申請資格。
