# DOING v20 未完成功能／阻斷分級

更新：2026-08-20 15:07（Asia/Taipei）

## 本輪判定規則

- **阻斷性且功能本體已存在**：直接修正，不另開第二套功能。
- **使用者已能進入流程，但做到一半會中斷**：視為半成品，必須補到可完成。
- **尚未開發、尚未形成正式入口的未來功能**：保留世界樹 `later`，本輪不假裝完成，也不為了湊數另開資料表。
- **功能已存在但需要真實 LINE／手機／付款／正式場次才能驗證**：保留 `verify`，不可用模擬冒充真人 PASS。

## 本輪已修正的阻斷／結構問題

1. 「我的紀錄」與「我的報名」名稱分裂：正式名稱統一為 **我的報名**；主資料固定 `registrations`；會員全域查詢固定 `getMyRegsGlobal`。
2. 同功能重複架構：名稱 SSOT 明定相容 hash／舊網址只能轉接同一實作，不得新增同義資料表或第二套 API。
3. 營運申請人工審核成為正常流程阻斷：改為 LINE 驗證後自動建立唯一工作空間；只有身分衝突／必要資料異常／建立失敗才進 `platform_risk_cases` 人工複核。
4. 90 天資料量治理：只清未驗證且未形成正式關聯的申請暫存、以及無 `registration_id` 的匿名曝光事件；正式營運資料不清。
5. 重複索引：`idx_tenant_apply_logs_status_created_v2` 與既有索引功能重複，發布 migration 時移除 `_v2`，避免每次寫入多做一份索引維護。
6. 舊 about／第二層頁面：PR #116 已物理刪除舊 about script/css，about/member 只保留 redirect-only 相容入口。

## 已有功能但仍需真人 UAT（不是程式缺口）

以下屬 `verify` 類：程式／資料路徑存在，但需要正式裝置、帳號或真實資料條件。不能因無法代替真人點擊而重做功能。

- LINE 會員跨頁／重登後智慧客服對話續接。
- 低信心智慧回答 → 平台改善佇列 → 真人審核／發布。
- 正式平台總管登入與客服原串回覆。
- 新工作空間重新整理後僅顯示已開通模組。
- 曝光 → 點擊 → 真實完成報名歸因。
- 會員中心手機／桌面正式視覺。
- 新租戶從零建立第一個營運項目。
- 前台報名 → 主辦審核 → 付款／退款完整真實場次。
- 真實場次財務結案。
- 真實手機現場操作、LINE 內建瀏覽器、通行碼。
- 活動前 7 天自動排位與通知。
- 拍照框 2160×3840、後鏡頭、LINE／一般瀏覽器真機。
- 世界樹手機閱讀與 Incremental Verification 的正式環境驗證。

## 尚未開發／未形成正式入口（保留 later，不屬本輪半成品）

世界樹目前仍有 16 項 `later`。依現有功能地圖分成三類：

### A. 攤商業績與保證金（5）
- 攤商填寫當日營業額。
- 不提供 NT$0 快速選項。
- 管理者不可修改攤商業績。
- 完成回報後啟動保證金退還。
- 真實場次結案驗收。

現況：只有需求／資料庫盤點，尚未有正式 Worker 讀寫閉環與正式入口，因此不是「使用者做到一半卡住」；本輪不新增同功能異名資料表。

### B. 寄賣與 POS（5）
- 寄賣檔期設定。
- 寄賣申請與審核。
- 商品與條碼。
- POS 銷售。
- 完整庫存與結算 E2E。

現況：尚未形成正式可操作流程。屬獨立大型模組，不能在本輪名稱／申請／資料治理修正中偷偷新增另一套資料架構。

### C. 未來擴充（6）
- 租戶自有網域與代設定。
- 自動候補與遞補期限。
- 套票、次數券與會員方案。
- 美類服務功能表與顧客到店／開始／完成操作。
- AI 活動主視覺生成。
- 自動化行銷流程。

現況：世界樹已登記但尚未列入目前 Release DoD；維持 `later`，後續依決策逐一開發，不建立猜測資料表。

## 結論

本輪沒有發現「已經開放給使用者操作、但中途沒有下一步」而需要立即偷偷擴建的新模組；目前真正的阻斷集中在名稱分裂、申請正常流程、舊頁殘留與資料保留治理，已納入 PR #116 修正。其餘 `verify` 交給真人 UAT；`later` 保持未開發，不重做、不假完成。
